# 交付格式

## 只交这几样

```
交付/
├── notes.json
├── manifest.json
├── 处理日志.md
└── 自检输出.txt
```

任务书、数据、工具都不用打回来。

## notes.json

```json
[
  {"n": 1, "versions": ["宋本"], "text": "注文正文…"},
  {"n": 1, "versions": ["宋本"], "text": "同条第二段…"}
]
```

| 字段 | 类型 | 规则 |
|---|---|---|
| `n` | 整数 | L1 骨架条号。**本书不建第二套编号** |
| `versions` | 数组 | 全书一致，填任务书指定值 |
| `text` | 字符串 | 纯文字。无 `<>`、无 `属性：`、无硬换行、无占位词 |

- 同一条注分几段就写几条记录，`n` 相同，按原顺序。
- 条号必须单调不减。跳号可以（注本不全注），倒序不行。
- `text` 里可以保留原书的 `【总论】` `【方】` 这类前缀标记。

## manifest.json

```json
{
  "id": "注本ID",
  "name": "书名（注者）",
  "targets": ["宋本"],
  "base": "作者、书名、成书年、电子文本出自哪一版",
  "source": "数据/文件名（字节数，C5 编号，分级）",
  "layer": "L2",
  "status": "录入中",
  "条数": 0,
  "覆盖": "0/398",
  "text_source": "用的是哪份电子文本、版本判定说明",
  "proof_level": "对照阅读级（未逐字对原书影印）"
}
```

`base`／`text_source`／`proof_level` 必填。写不准写「不明（原电子文本无底本声明）」，不许留空。

## 处理日志.md

必须写四件事：

1. **做了什么**——扫了哪些页／篇，挂了多少条。
2. **没做什么**——哪些段没核、哪些只粗分、有没有对原书影印。
3. **卡在哪**——挂不上的注、原书顺序与骨架不一致的地方。
4. **不确定的**——错字疑点、条号判断依据薄弱的条目。

**「逐字过，未见需改」这类话会被直接退回。**

## 自检输出.txt

```bash
python3 工具/自检_注本.py 交付/ --side sh    # 或 --side jg
```

把终端输出原样存进这个文件。不许手抄、不许改数。

## 回传

一个 zip，包内顶层是 `交付/`：

```
注本ID_回传.zip
└── 交付/
    ├── notes.json
    ├── manifest.json
    ├── 处理日志.md
    └── 自检输出.txt
```
