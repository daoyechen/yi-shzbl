## 三、产出（只这两份）

### 1. `notes.json`

```json
[
  {"n": 1, "versions": ["{{版本名}}"], "text": "注文正文…"},
  {"n": 1, "versions": ["{{版本名}}"], "text": "同条第二段…"},
  {"n": 2, "versions": ["{{版本名}}"], "text": "…"}
]
```

| 字段 | 规则 |
|---|---|
| `n` | **L1 条号**，整数，1..{{N}}。**本书不建自己的条号** |
| `versions` | 固定填 `["{{版本名}}"]`，全篇一致 |
| `text` | 该条注文，**纯文字**。不带 `<>`、不带 `属性：`、不带硬换行、不带「待核」这类占位 |

**一条注有多段**（原书分段落）就写多条记录，`n` 相同，按原顺序排列。下游按 `n` 聚合。

### 2. `manifest.json`

```json
{
  "id": "{{id}}",
  "name": "{{注本名}}（{{注者}}）",
  "targets": ["{{版本名}}"],
  "base": "底本：作者、书名、成书年、这个电子文本出自哪一版",
  "source": "数据/{{文件名}}（{{字节}} 字节，{{C5编号}}，分级 {{C5分级}}）",
  "source_page": "书页区间；电子文本无页码时写“电子文本，无页码”",
  "layer": "L2",
  "status": "录入中",
  "条数": 0,
  "覆盖": "0/{{N}}",
  "text_source": "{{文件名}}，来源与版本判定说明",
  "proof_level": "对照阅读级（残错 ≤2%，未逐字对原书影印）",
  "files": {
    "原样": "转录_原样.md（只读）",
    "校订": "转录_校订.md（可迭代）",
    "校正表": "校正表.csv（页/原文/改文/依据）"
  }
}
```

`base`／`source_page`／`text_source`／`proof_level`／`files` **必填**。纸页无法定位时写「电子文本，无页码」或「原件未得」，来源不明写「不明（原电子文本无底本声明）」，不许留空。

## 四、怎么切、怎么挂

**切条靠 `n`，不靠段落。** 步骤：

1. 打开 `骨架_{{侧}}_{{N}}条.json`，把每条 `原文` 的前 8–10 个字记住。
2. 在注本文本里找这些字的**注释对象**——注本通常先引一句经文再注，那句引文就是锚。
3. 锚上的条，把紧随其后的注文收进 `text`，`n` 填骨架条号。
4. 原书有「此承上条」「上条」这类指代，按上下文归到对应条，归不了就归到最近的上一条并**在处理日志里写明**。
5. 全书扫完核对：`n` 必须**单调不减**，跳号允许（注本不全注），倒序不允许。

**挂不上条的注**（总论、序、凡例、方歌、 book-level 议论）：
- 属于全书总论的，`n` 填它实际讨论的第一条，并在 `text` 前加 `【总论】`；
- 纯方剂内容而 L1 该条无方，归到该条，`text` 前加 `【方】`；
- 完全挂不上的，**不要塞进任何条**，写进 `交付/挂不上清单.md`（条数、原文首 40 字、为什么挂不上）。

## 五、不许做的事

1. **不改经文。** 注本里引的经文与骨架不一致时，注文照原样录，不许按骨架改注文。
2. **不补字、不猜字。** 电子文本里的错字、缺字照原样留，写进处理日志。宁可留错，不许编。
3. **不合并条。** 骨架两条合并成一条、或把一条拆成两条，都不许。
4. **不重排。** 原书顺序与骨架顺序不一致时，按骨架 `n` 排，但在处理日志里写明「原书此处顺序不同」。
5. **不写自己的条号体系。** 交付里出现 `n` 之外的第二套编号即退回。

## 六、交付

**只交 `交付/`，不要把任务书、数据、工具打回来。**

```
交付/
├── notes.json
├── manifest.json
├── 处理日志.md      ← 做了什么、卡在哪、哪些没核、哪些挂不上
└── 自检输出.txt     ← 自检脚本原始终端输出，不许手抄
```

`处理日志.md` 必须写**「没做什么」**。正面例子：

> 实做 p1–p40 逐条挂条；p41–p60 只按篇题粗分，未逐条核锚点；全书未对原书影印核对，残错未知。

反面例子（会被退回）：

> 逐字过，未见需改。

**回传命名**：`{{id}}_回传.zip`，包内顶层目录 `交付/`。

## 七、硬伤（一处即退）

| 项 | 判据 |
|---|---|
| 条号越界 | `n` 不在 1..{{N}} |
| 条号倒序 | 后一条 `n` 小于前一条 |
| 占位残留 | `text` 含「待核／未决／存疑／TODO／？？」 |
| 标签残留 | `text` 含 `<` `>` 或 `属性：` |
| 空正文 | `text` 汉字 < 5 |
| 契约缺字段 | manifest 缺 `base`／`source_page`／`text_source`／`proof_level`／`files` |
| 自检未跑 | 无 `自检输出.txt` |

## 八、自检（交付前必跑）

```bash
python3 工具/自检_注本.py 交付/ --side {{sh|jg}}
```

硬伤必须为 0。提示项（硬换行、碎片段）可以留，但要在处理日志里说明。

## 九、验收口径

**对照阅读级**：残错 ≤2%，错处不影响读懂注文即收。硬伤零容忍。
我方验收会抽 3–5 条对原书影印复核，抽到硬伤即整包退回。
