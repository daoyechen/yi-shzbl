## 1. 本任务是什么

把 `数据/{{文件名}}` 这部注本，按 L1 骨架条号切成 `notes.json`。

- **判定类型**：人工为主（机器只能切段与初筛，条号归属须人判）。机器可代劳：转码、去标签、并硬换行、按骨架前 8 字粗定位。
- **收益类别**：**V1 可读内容**（该注本此前无结构化文本，做完即上对照页）。
- **本任务不做什么**：不转录原书、不裁定版本优劣、不补字、不做校勘记。
- **承接人第一步**：打开 `数据/骨架_{{侧}}_{{N}}条.json`，把第 1 条 `原文` 前 10 字记住，再在 `数据/{{文件名}}` 里找它第一次出现的位置，照此挂第一条；跑通一条后再全书推进。

## 2. 依赖与写隔离

依赖顺序：`数据/` 全文与骨架（已随包给齐） → 本任务 → 我方合库上页。
并行范围：无。本书不与别的包共享任何可写文件。

**写模式：只读处理（A）。**

- 项目主数据、`50_data/51_notes/`、台账、manifest 契约、门禁阈值：**一律只读，不改**。
- 只写你自己包内的 `交付/` 目录。
- **入账由我方做**，承接人不合并、不改名、不往主库贴数据。
- 包里不含任何项目数据库文件；若发现包内有 `db`／`state/`，立即报告，不要使用。

## 6. 产出（这四份 + 清单）

### 6.1 `notes.json`

```json
[
  {"n": 1, "versions": ["{{版本名}}"], "text": "注文正文…"},
  {"n": 1, "versions": ["{{版本名}}"], "text": "同条第二段…"},
  {"n": 2, "versions": ["{{版本名}}"], "text": "…"}
]
```

| 字段 | 规则 |
|---|---|
| `n` | **L1 条号**，整数，1..{{N}}。**本书不建自己的条号** |
| `versions` | 固定填 `["{{版本名}}"]`，全篇一致 |
| `text` | 该条注文，**纯文字**。不带 `<>`、不带 `属性：`、不带硬换行、不带「待核」这类占位 |

**一条注有多段**（原书分段落）就写多条记录，`n` 相同，按原顺序排列。下游按 `n` 聚合。

### 6.2 `manifest.json`

```json
{
  "id": "{{id}}",
  "name": "{{注本名}}（{{注者}}）",
  "targets": ["{{版本名}}"],
  "base": "底本：作者、书名、成书年、这个电子文本出自哪一版",
  "source": "数据/{{文件名}}（{{字节}} 字节，{{C5编号}}，分级 {{C5分级}}）",
  "source_page": "无页可指（电子文本，非影印）／或具体卷页",
  "files": ["notes.json", "manifest.json", "处理日志.md", "自检输出.txt", "挂不上清单.md"],
  "layer": "L2",
  "status": "录入中",
  "条数": 0,
  "覆盖": "0/{{N}}",
  "text_source": "用的是哪份电子文本、版本判定说明",
  "proof_level": "对照阅读级（未逐字对原书影印）"
}
```

`base`／`source_page`／`text_source`／`proof_level`／`files` **必填**，写不准就写「不明（原电子文本无底本声明）」，不许留空。

### 6.3 `处理日志.md`

四段，缺一段退回：

1. **做了什么**——逐篇扫了哪些、挂了多少条、每篇多少条（给表）。
2. **没做什么**——哪些段未核、有没有对原书影印、哪些步骤跳过了。
3. **卡在哪**——挂不上的、原书顺序与骨架冲突的、切分点由你判断的位置（要标明是整理者切分，非原书分段）。
4. **不确定的**——条号依据薄弱的条目（给 `n` + 原文首 40 字）、电子文本残字（给 `n` + 原字）。

**「逐字过，未见需改」这类无据结论会被直接退回。**

### 6.4 `挂不上清单.md`

只列成段却挂不上任何条的文字：编号、原书位置、原文首 40 字、字数、为什么挂不上。
标签行、著录行（书名/作者/朝代/年份）不算正文，另设一节列出即可。

## 7. 怎么切、怎么挂

切条靠 `n`，不靠段落：

1. 打开骨架，把每条 `原文` 的前 8–10 个字记住。
2. 在注本文本里找这些字的**注释对象**——注本常先引一句经文再注，那句引文就是锚。
3. 锚上的条，把紧随其后的注文收进 `text`，`n` 填骨架条号。
4. 原书有「此承上条」「上条」这类指代，按上下文归到对应条，归不了就归最近上一条并**在日志里写明**。
5. 全书扫完核对：`n` 必须**单调不减**，跳号允许（注本不全注），倒序不允许。

**挂不上条的注**（总论、序、凡例、方歌、全书议论）：

- 属全书总论的，`n` 填它实际讨论的第一条，`text` 前加 `【总论】`；
- 纯方剂内容而 L1 该条无方，归到该条，`text` 前加 `【方】`；
- 完全挂不上的，写进 `挂不上清单.md`，**不要塞进任何条**。

## 8. 不许做的事

1. **不改经文。** 注本引的经文与骨架不一致时，注文照原样录，不按骨架改注文。
2. **不补字、不猜字。** 错字、缺字照原样留并记入日志。宁可留错，不许编。
3. **不合并条、不拆条。** 骨架两条并一条、一条拆两条，都不许。
4. **不重排骨架。** 原书顺序与骨架不一致时按骨架 `n` 排，在日志写明「原书此处顺序不同」。
5. **不写第二套编号。** 交付里出现 `n` 之外的自编号即退回。
6. **不改主库。** 不写 `50_data/`、不改台账、不改契约、不改自检阈值。
7. **只用包内 `数据/` 的文件。** 不要另找同名书、不要用网上另下的版本替代。
   若发现包内文件与任务书所述书不符（作者、篇目、卷次对不上），**立即停工并报告**，不要自行换源。
7. **只用包内 `数据/` 的文件。** 不要另找同名书、不要用网上另下的版本替代。
   若发现包内文件与任务书所述书不符（作者、篇目、卷次对不上），**立即停工并报告**，不要自行换源。

## 9. 交付与回传

**只交 `交付/`**，不要把任务书、数据、工具打回来。

```
交付/
├── notes.json
├── manifest.json
├── 处理日志.md      ← 做了什么、没做什么、卡在哪、哪处不确定
├── 挂不上清单.md    ← 成段却挂不上的文字
├── 自检输出.txt     ← 自检脚本原始输出，不许手抄
└── PACK_VERSION.md  ← 派发包 SHA256 + 生成时间（随包已给，照抄）
```

**回传命名**：派发包名去掉 `.zip` 再加 `_RETURN.zip`。即

```
派发  01_02_伤寒医诀串解_yijue_sh_派发包.zip
回传  01_02_伤寒医诀串解_yijue_sh_派发包_RETURN.zip
```

去掉末尾 `_RETURN` 就是派发包名，便于对账。修订版在包名加 `_r2`、`_r3`（`…_派发包_r2.zip` → `…_派发包_r2_RETURN.zip`），**不得同名覆盖**。

## 10. 硬伤（一处即退）

| 项 | 判据 |
|---|---|
| 条号越界 | `n` 不在 1..{{N}} |
| 条号倒序 | 后一条 `n` 小于前一条 |
| 占位残留 | `text` 含「待核／未决／存疑／TODO／？？」 |
| 标签残留 | `text` 含 `<` `>` 或 `属性：` |
| 空正文 | `text` 汉字 < 5 |
| 契约缺字段 | manifest 缺 `base`／`source_page`／`text_source`／`proof_level`／`files` |
| 自检未跑 | 无 `自检输出.txt` |
| 日志失实 | 未写「没做什么」，或写「逐字过，未见需改」这类无据结论 |

## 11. 自检（交付前必跑）

```bash
python3 工具/自检_注本.py 交付/ --side {{侧}}
```

硬伤必须为 0。提示项（硬换行、碎片段）可以留，但要在处理日志里说明。

## 12. 验收口径

**对照阅读级**：残错 ≤2%，错处不影响读懂注文即收。硬伤零容忍。

我方会：独立复跑自检（不复用你的输出）、抽 3–5 条对骨架原文核条号、抽 8 条核正文洁净度。
**目标值不等于实测值**：我方只写在本次抽检范围内发现问题与否，不写「已达标」。

## 13. 传输失败时的降级（仅通道出问题时）

只处理已拿到的材料，执行逐条挂条；不改骨架、不裁定、不补字；
缺件记路径、已试步骤与卡点；结果放 `交付/`，古籍引文原样保留。
缺关键输入的步骤暂停，不以另一部书替代，不虚报结项。
