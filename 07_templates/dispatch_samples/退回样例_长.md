## ⓪ 先花两小时试繁体模型（在修正表之前）

现在链路是「RapidOCR 中文(简) → OpenCC s2t → 修正表」，**s2t 是最大误差来源**。先换繁体模型试：

- PaddleOCR `chinese_cht_PP-OCRv3/v4` 的 rec 模型导出 ONNX
- 或 RapidOCR 加载自定义 rec 模型：`RapidOCR(params={"Rec.model_path": "...chinese_cht...onnx"})`

**验收两条都要过**：① bigram 不低于现在 82%；② 人工核这 6 页，`雲/餘/幹/發` 四类错必须降到 0。

过 → 用繁体模型，① 的修正表作废。不过 → 退回 s2t + 修正表。**别耗超过半天。**

## ① s2t 的错是确定性的，不能靠 10% 抽验

我从你的六页里查出来的——

| 字 | 实测 | 应作 |
|---|---|---|
| `雲` | **9 次里 7 次错**（陳平伯雲、內經雲、之上雲者、本論雲、至雲惟小柴胡） | 云 |
| `餘` | 餘特補之 | 余 |
| `幹` | 氣逆而內幹 | 干 |
| `發` | 非細心如發者 | 髮 |

这些 **100% 稳定复现**，抽不到就等于没查。全书必须用规则全库扫，逐条记命中数。

## ② 「曰」错成「日」6 处

`【補日】`、`【正日】`、`故日氣之標`、`名日命門`、`餘日`、`日：`。

「曰」是注文最高频的字，错一个就断句。全库扫 `補日`/`正日`/`故日`/`名日`/`日：`。

## ③ 标记词括号没兜住

残留 `【補日］`、`【正日］`——左括号对了、**右括号还是 `］`**。你现在的规则只在左括号被替换时触发。全书保证 `【`…`】` 成对且内层白名单。

## 一个必须改的认知：bigram 85% ≠ 干净

**p32 的 bigram 86.9%，比干净文本基线 85.8% 还高**，但同页我人工核出约 25 处错字：

```
㕮咀 → 收咀×1、哎咀×1（正确 0 次）
去滓 → 去澤×2、去溶×1（正确 0 次）
五苓散 → 江苓散  麻黃 → 麻奠  桂枝 → 佳枝/桂校  太陽 → 太階/太阿
入 → 人  五处：直人、陷人、匯人、絲絲人扣、人於
```

这个指标只能拦灾难（63% 那份），拦不住 1–2% 级错误。**所以全书不能只拿 bigram 当凭据。**
