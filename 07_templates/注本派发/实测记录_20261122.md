# 电子本实测记录（2026-11-22）

派包前我方对两部做了实测，结果决定了任务书里「怎么切条」的写法。**先看这页，能省你两小时。**

## 一、这批电子本的共同特征

都是「中医典籍」类结构化文本，GBK/GB18030 编码，标签形如：

```
<篇名>篇名或方名
属性：正文…
\x方名\ 或 \x一条\    ← 原书的方名／条次标记，形态不一
```

- **编码**：全部 gb18030。包内已转成 UTF-8，不用再转。
- **硬换行**：原书按行宽断的，行尾都带换行。入库时要并回整段（`text` 里不许有 `\n`）。
- **不用收的部分**：`<目录>` 之后到下一个 `<篇名>` 之前是目录列表，别当正文。

## 二、B21 金匮方歌括（实测：不能机械做）

| 项 | 实测 |
|---|---|
| 规模 | 37,916 汉字，248 个 `<篇名>` |
| **短行占比 27%**（≤4 汉字的行） | **严重串行** |
| 形态 | 每个 `<篇名>` 是一个**方名**，其下是方歌＋方解 |

**串行是什么样**——原书夹注（小字）被拆成独立行插进正文流：

```
属性：辛未秋孟。元犀趋保阳。承膝下欢。窃见家君公事稍暇。取伤寒、金匮等书业已三四注 
者。 
节劳 
一十 
注之 
```

「节劳／一十／注之」是夹注碎片，被插在「三四注者」之后。**还原需要逐篇判断哪几行是夹注、插回哪里**，不能用规则自动拼。

另有简转繁残留：`浓朴`（应厚朴）、`必 齿`（应必齘齿，缺字）。

**结论：这部要人工逐篇重排，1 天量级。别指望脚本。**

## 三、B7 高注金匮要略（实测：最接近可机械，但仍需人工核）

| 项 | 实测 |
|---|---|
| 规模 | 153,401 汉字，23 个 `<篇名>`（按篇，不是按条） |
| **短行占比 2%** | 文字干净，行内文气连贯 |
| 条标记 | 467 个 `\x一条\x` ～`\xN条\x`，**但只有部分篇有** |
| 覆盖 | 血痹虚劳、肺痿肺痈、胸痹、腹满、痰饮、水气、呕吐哕等篇有；脏腑经络先后、百合狐惑、妇人三篇、杂疗、禽兽鱼虫**没有** |

有标记的篇，`\x三条\x` = 该篇第 3 条，可直接对骨架篇内序号。
无标记的篇，要用篇内 `\x方名\x` 标记＋经文首句去对骨架，或人工分段。

**结论：能省一半工，剩下靠人工。适合做「切条」这一步的试点。**

## 四、其余 7 部：未实测，按同批处理

同一来源，编码与标签格式一致；串行程度未知。**先抽 3 篇看短行占比**，再决定用脚本还是人工：

```bash
python3 - <<'EOF'
import re
t=open("数据/×××.txt",encoding="utf-8").read()
lines=[l.strip() for l in t.split("\n") if l.strip()]
short=[l for l in lines if 0<len(re.findall(r"[\u4e00-\u9fff]",l))<=4]
print("行%d 短行%d 占比%.0f%%"%(len(lines),len(short),len(short)*100.0/len(lines)))
EOF
```

短行 <5% 可按 B7 的路子走；>20% 按 B21 的路子，纯人工。

## 五、给你的建议顺序

1. **先做 `伤寒审证表`（2.0 万字）**——最短，一天内能跑完整个流程，把格式跑通。
2. 再做 `伤寒医诀串解`（3.2 万字）、`伤寒论类方`（4.8 万字）。
3. `金匮方歌括` 放最后或不做——串行 27%，投入产出比最差。

长篇（`伤寒溯源集` 20 万字、`伤寒论纲目` 20 万字）先确认是否全文，再决定拆不拆半。
