# 跑起来（编译、发布、JG 全链路）

> 从 `AGENTS.md` 搬出。**这是操作手册，不是硬规则。** 规则看 `AGENTS.md`。

## 编译

```bash
python3 08_tools/build_index.py --check   # 只检查；有变化 exit 2
python3 08_tools/build_index.py           # 有变化才编译（gujia + zhushi + 落地页）
python3 08_tools/build_index.py --force   # 强制重编
python3 08_tools/build_index.py --site zhushi --force   # 只重编一个站
```

产出**两个站**，共用一个模板、一套骨架：

| 站 | 数据 | 备注 |
|---|---|---|
| `gujia/` | L1 原文，剥掉 `viewer_data.notes` | 骨架版，页面上不出现任何注文 UI |
| `zhushi/` | L1 原文 + `zhub`／`zhu`（来自 `50_data/51_notes/`） | 注文只读 L2，不回写 L1 |

`<站>/data/manifest.json` 是台账（条数、版本数、review 数、异文条数、源/产物 sha256；zhushi 另有 `l2` 段记注文 sha 与注本数）。**是否最新以 manifest 与实际文件比对为准，不看时间戳。**

注文条号越界、注本下标失效会让编译直接失败——挂着错条的注比少几部注本坏得多。


## 发布

`index.html` 与 `data/` **必须同一次提交推**，只推一个会报「Failed to fetch」（缓存错配，不是代码坏）。必须走 http(s)，`file://` 下 fetch 被拒。详见 `docs/前端约定.md` §五。
