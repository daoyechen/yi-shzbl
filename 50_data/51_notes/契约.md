# 51_notes · L2 注本契约

> 本文件是 L2 字段、目录、锚点和验收的唯一详规。具体注本数据落在本目录。
> 本层寄生于 L1 原文对照（`50_data/52_l1_assembly/jingui/`、`50_data/52_l1_assembly/shanghan/`），不另立条号：条注锚 L1 条号，总论/篇级说明用 `scope=book/pian`。

## 一、L2 是什么

L1 = 多版本**原文**逐条对照（当前主体，产出以原文为主）。
L2 = 在各版原文之上，叠加**注释本**的注文对照。

注释本的特点，决定了数据结构：

| 情形 | 例子 | 锚点写法 |
|---|---|---|
| 只注一本（多数） | 桂林古本某注本 → 只讲桂林古本 | `versions: ["桂林古本"]` |
| 注多本（少数） | 某注本兼论桂林古本与宋本之异 | `versions: ["桂林古本","宋本"]` |

所以条注的身份是 **(骨架条号 n, 所注版本列表)**；笔记的身份是 **(scope, 篇/标题, 所注版本列表)**。不是一个注本一张表。

## 二、目录约定

```
50_data/51_notes/
  契约.md                   本文件
  00_注本清单.csv           所有注本的登记台账（唯一索引）
  图版/<注本ID>/            图版：原图 + figures.json（见 §3.2）
  03_材料分级与众包台账.md    W 工法分级 / P 版权分级 / 众包切法
  04_图版方案.md             图版存储与显示方案
  _模板/                    新注本照抄
    manifest.json           注本元信息
    notes.json              注文（空数组起步）
  <注本ID>/                 实际注本，按需创建
    manifest.json
    notes.json
```

**注本 ID**：小写拼音/拉丁，全局唯一，不含中文与空格，如 `guilin-zhu`、`songben-chengwuji`。

## 三、数据契约

`manifest.json`

```json
{
  "id": "guilin-zhu",
  "name": "桂林古本××注",
  "targets": ["桂林古本"],
  "base": "注本自身的版本与出处（人、年、刊本）",
  "source": "原件在哪（馆藏/影印/转录），无则写「未得」",
  "source_page": "书页区间；电子文本无页码时写「电子文本，无页码」",
  "layer": "L2",
  "status": "目录 | 录入中 | 已核",
  "text_source": "OCR（引擎+版本） 或 电子文本（文件名+台账编号），见 AGENTS 硬规矩 20",
  "proof_level": "对照阅读级（残错 ≤2%） | 校勘级（另立项）",
  "files": {
    "原样": "转录_原样.md（只读，繁体，含错）",
    "校订": "转录_校订.md（可迭代）",
    "校正表": "校正表.csv（页/原文/改文/依据）"
  }
}
```

`base` / `source_page` / `text_source` / `proof_level` / `files` 五个字段**必填**（项目硬规矩 3、13）。
有笔记的注本另写 `条注数` / `笔记数`；`条数` 仍是两类的总段数。纸页无法定位时必须明确写「电子文本，无页码」或「原件未得」，不许编造页码。
理由：以后要升校勘级、与别本对校、对外引用，都从这四个字段起手；缺了就得重建出处。
`proof_level` 决定验收尺子——**对照阅读级不许拿零错去卡**（AGENTS 硬规矩 18）。

`notes.json`（数组，每条一个注文单元）

```json
[
  { "n": 12, "versions": ["桂林古本"], "text": "注文原文", "pg": 34 },
  { "n": null, "scope": "pian", "pian": "辨太阳病脉证并治上第五  合一十六法  方一十四首",
    "title": "太阳总论·发汗利水", "versions": ["宋本"], "text": "【总论】…", "pg": 34 },
  { "n": null, "scope": "book", "pian": null, "title": "读法·伤寒杂病合论",
    "versions": ["宋本"], "text": "【总论】…", "pg": null }
]
```

- `n`：**L1 骨架条号**，不是注本自己的条号，也不是注本页码；`scope` 为 `book`/`pian` 时为 `null`。
- `versions`：这条注文针对哪一版原文；跨版比较就写多值。
- `pg`：注本自身页码，可为 `null`（未得就写 null，不许编）。
- 注文**逐字照录**，异体字不校；读不全写「仅可辨…」，不补。

### 3.1 可选扩展字段（**2026-11-16 新增，批次1 起使用**）

上面四个字段是**必需**的。以下三个是**可选**的，只在需要时出现，不写即视为默认：

| 字段 | 类型 | 语义 | 谁在用 |
|---|---|---|---|
| `seg` | int | 同一条下的第几段。一条注文被拆成多段时递增（1,2,3…）；不拆就不写 | 批次1 全部四包 |
| `attr` | string | 这段话**是谁说的**：`唐容川` / `陈修园` / `引文` / `方剂` | 唐容川两包（合编本，一书多人语） |
| `n_span` | int | 本条注文实际**跨到**第几条（含起条）。默认不写 = 只覆盖 `n` 一条 | 暂未使用，为「一节含数条」预留 |
| `scope` | string | 锚点层级：`tiao`（默认，条注）／`pian`（篇级总论）／`book`（全书读法、序例） | 2026-11-24 起，总论独立 |
| `pian` | string | `scope=pian` 时的 L1 篇名，原样照录；`book` 为 `null` | 同上 |
| `title` | string | 笔记标题，6–20 字；`scope` 非 `tiao` 时必填 | 同上 |

约束：

1. **扩展字段只增不改，不动 `n`/`versions`/`text`/`pg` 的语义。**
2. `seg` 在同一 `n` 内必须从 1 起连续、不重复。
3. `attr` 是**合编本专用**。单一作者的注本不许加 `attr`——加上去等于给全集标同一个值，无信息量。
4. `n_span` 一旦使用，`n` 仍必须是**起条**；跨条注文**不许**复制成多条记录（那是虚增条数）。
5. 新增扩展字段必须在本表登记，不许在包内自创字段名。
6. `scope` 默认 `tiao`。`book`/`pian` 时 `n` 必须为 `null`，`title` 必填；`pian` 时 `pian` 必填且用 L1 篇名，不自造篇号。
7. 计数分两本账：`条注数` 只算 `scope=tiao`，`笔记数` 算 `book`+`pian`；`覆盖` 只按条注的 `n` 去重计算。manifest 两字段都写，旧包没有则按全条注处理。

### 3.2 图版：`figures.json`（**2026-11-16 新增**）

带图的书（现代讲稿尤其常见）除 `notes.json` 外，**另交一份 `figures.json`**，图存 `图版/<注本ID>/`。
完整设计与显示方案见 [`04_图版方案.md`](04_图版方案.md)，这里只留硬规矩：

1. **图内嵌靠图注编号，不靠位置。** 正文「（图57）」→ 找 `cap=="图57"` 的图。拿字符位置反推条归属实测不可靠（李阳波 62 条只成 19 条，且集中误挂）。
2. **`cap` 同一注本内必须唯一。** 抓不准就写 `null`，不许猜一个。
3. **`n` 判不出写 `null`。** 不许按「插在第几段」推条号。
4. **原图保留 epub 内原文件名**，不重命名 —— 重命名等于断掉溯源。
5. 无 `cap` 的图进「图版集」，不内嵌正文。

## 四、与 L1 的耦合（改 L1 前必读）

L2 全部锚在 L1 的骨架条号上。**L1 一动，L2 必然要跟。**

| L1 变更类型 | 对 L2 的影响 | 处理 |
|---|---|---|
| 只改原文用字、不改编号 | 注文不受影响 | 无需动 |
| 条号调整（增/删/改序） | 锚点全错 | 必须按 `n_map.json`（旧→新）逐条重挂，并人工抽查 |
| 版本增删 | `versions` 里可能指向不存在的版本 | 逐注本核对 `targets` 是否仍有效 |
| 骨架换底本 | L2 整体作废重来 | 不要试图迁移，重新对接 |

**硬要求**：L1 若动编号，必须同时产出 `50_data/51_notes/n_map.json`
（`{"旧号": 新号, ...}`，无变化也写空表），否则 L2 无法机械重挂，只能人工重做。

## 五、边界（别越线）

1. **注文不许写进 L1 的 `viewer_data.json`。**
   L1 的 `notes` 字段语义是「条号 → {版本: 注文}」，历史上 SH 侧曾把注释塞进去（372 条成无己注），
   属于 L1/L2 混写。SH 基线只读、暂不迁移；**L2 新数据一律落在本目录**。
2. **本层不建条号。** 没有自己的编号空间，永远引用 L1。
3. **不在这里做原文校勘。** L2 只记录注本说了什么，不判断注本对不对。
