# 版本命名规范

> 生效:2026-11-04
> 依据:用户指令 —— 「每次有调整就用新的版本命名;大改升中版号,小改升小版号」

---

## 一、两套编号,各管各的(务必分清)

| 概念 | 含义 | 写法 | 例子 |
|---|---|---|---|
| **收录版本套数** | 这个数据集收录了几个《伤寒论》传本 | 阿拉伯数字 + 「版」 | 11 版 = 宋本骨架 + 9 个对照版 |
| **产出迭代号** | 这个**交付物**的第几版 | `v主.次.修订` | `v0.11.1` |

**文件名一律用迭代号**,不再用「11 版」当迭代标识 —— 否则「11 版」既指内容范围又指文件版本,必然混淆。
「11 版」只在**描述内容范围**时使用(如「11 版对照」),不出现在文件名里。

---

## 二、迭代号规则

```
v主.次.修订
│  │  └── 修订号(patch):小改
│  └───── 次版本号(minor):中改
└──────── 主版本号(major):大改
```

### 什么时候升哪一级

| 级别 | 判据 | 例子 |
|---|---|---|
| **升次版本号**(v0.11.0 → **v0.12.0**) | **新增版本 / 新增内容大改** | 新增第 12 个传本;换骨架;总装口径变更;新增独立维度(如注文层) |
| **升修订号**(v0.11.0 → **v0.11.1**) | **表现层/引擎修复,数据口径不变** | 修 bug;补字段;改渲染;加自检;文案调整 |
| **不动版本号** | 仅重新打包、无任何内容变化 | — |

### 判定的硬标准

**数据口径变没变** 是唯一分水岭:

- `viewer_data.json` 的 `items` / `fang` / `indep` / `review` / `stats` / `notes` / `reason` **任一发生变化** → 至少升次版本号
- 只有 `pian` / `spian` / `spianMap` 等**篇级或表现层**字段变化,或只有渲染代码变化 → 升修订号
- **引擎改动后必须 diff 验证**:主数字(对上/高置信/独立/方剂)与改前逐项一致,才可判为「小改」

> 判定流程见《引擎缺陷台账.md》「通用检查清单」最后一条:引擎改动后主数字必须与改前一致,变了就是误伤。

## 三、命名规则

### 主交付(单文件)

```
伤寒论多版本对照浏览器_v{主}.{次}.{修}.html
```

**单文件是主交付形态** —— 双击即开、不联网、便于转发给他人,这是这个项目的核心诉求。
维护版(拆文件)为**可选附属品**,不作为主交付。

### 维护版(拆文件,可选)

```
伤寒论多版本对照浏览器_v{主}.{次}.{修}_维护版.html
伤寒论多版本对照浏览器_v{主}.{次}.{修}_维护版_data.js
```

> ⚠ **不能用 `fetch()` 加载 data.json** —— 实测 `file://` 下 `fetch` 会被浏览器以 Origin null 拒绝
> (`TypeError: Failed to fetch`),页面直接白屏。必须用 `<script src="..._data.js">` 外链,
> 该方式在 `file://` 与 `http://` 下均正常。

### 结构化包

```
结构化对照_v{主}.{次}.{修}.zip
```

### 目录

```
03_总装产出_v{主}.{次}.{修}/
```

基线目录(`02_新版基线_11版/`)由**收录版本套数**决定,不随迭代号变 —— 除非收录版本数变了。

## 四、旧版处置

**新版本另起文件名,旧版一律保留,不覆盖。**
每次发布时在《版本台账.md》登记一行,写明:迭代号、日期、变更内容、数据口径是否变。
