## 一、为什么是「条」

《伤寒杂病论》整本对比阅读的框架,要求**一条坐标轴贯穿两半**。据此定:

| | 顶层坐标 | 子层 | 编号空间 |
|---|---|---|---|
| 《伤寒论》 | **条**(398,原书逐位汉字条号) | 各版异文分段 | `SH` |
| 《金匮要略》 | **条**(N,赵开美本条级) | 条内**句**级单元 | `JG` |

两套编号空间**彼此独立**,`SH-1` 与 `JG-1` 不是同一条,任何模块不得混用。

### 「条」的原书依据(非本项目发明)

1. 《伤寒论》宋本 398 条 = 原书逐位汉字条号(九九=99、三九八=398),零缺号,**不可再生**。
2. 《金匮要略》通行 25 篇,**前 22 篇计原文约 397 条（人卫 1964 校注本口径，逐篇合计 397；学界常说的「398 条」为该口径的概数，差 1 未归入任一方）；全 24 篇 472 条**,方 262 首(除附方 205)。
   ⚠️ **更正（2026-11-05，据 2_6 实测）**：此前据「《金匮》恰好各 398 条」立论"两半在坐标上对等"，该论断**不成立**。
   实测：人卫 1964 前 22 篇逐篇合计 **397** 条（与概数 398 差 1，账差未归入任一方）；
   全 24 篇 **472** 条（加篇 23「雜療方」15 + 篇 24「禽獸魚蟲禁忌」62 等宋本附编）。
   《伤寒论》侧 398 为**原书逐位汉字条号**（硬坐标），《金匮》侧 472/397 为**今人整理本条界**
   （赵开美本自身无逐条编号，仅篇下「論X首 脉證Y條」分类计数）。
   **两侧条数既不相等，来源层级亦不同**——不得再以「恰好各 398 条」作任何论证。
   本项目《金匮》侧实际顶层坐标为 **赵开美本条级 465 条**（据人卫 1964 条级参照系还原，含 1316 句级下钻），
   详见《规范/金匮骨架契约.md》§四 与《验收报告_第五批2_6回传.md》。
3. **原刻本自己按篇分条**:A4 四部丛刊影印图版卷二 P46 版心首列印
   「○婦人產後病脉證治第二十一 / **論一首　證六條　方八首**」—— 篇名行下明写本篇几条几方。

### 为什么不是「句」

赵开美本电子文本的**分段级**共 **1316 段**(原声明 1388,已剔 72 条网页 UI 残留)。
分段是**转录层的粒度**(一段就是一段),不是原书粒度:
同一条在明刻本里常被拆成数段(如第 1 篇「問曰:上工治未病…」与其后续三段合为学界第 1 条)。
若以分段为顶层,则「条」这一概念在两侧消失,整本框架无从谈起。

## 二、两层结构定义

### 顶层:条
```json
{
  "no": 1,                    // 条号,JG 编号空间,1..N 连续
  "篇": "臟腑經絡先後病脈證第一",
  "页": 3,                    // 影印原页(可回溯)
  "原文": "……整条全文……",
  "条界依据": "学界条界(A10 参照系)",
  "置信": "高置信",
  "待核校": false,
  "句": [                     // ← 子层:句级单元
    {"seq": 1, "原文": "……", "源no": 1, "页": 3, "置信": "高置信"}
  ]
}
```

### 子层:句
- 用途:版本学下钻。条内各句之间的异文,逐句可比。
- **与伤寒侧的 `分段` 字段语义不同**,故**不共用字段名**:
  - 伤寒侧 `分段` = 某版一条内对应多个宋本条的**异文分段**(既有语义,不动)
  - 金匮侧 `句`   = 同一条内的**句级单元**(新)
- 句级不得反向决定条级。**条级是骨架,句级是附属**。

## 三、条界判定规则(硬约束)

条界**不得**靠正则或相似度猜出。只能用以下三条证据:

| 优先级 | 证据 | 说明 |
|---|---|---|
| **①** | **现通行本条界** | 人卫 1964 排印本 / 学苑点校本,是**条级**排印。以其条界为参照系 |
| **②** | **原刻本体例行** | A4 影印图版每篇题下的「論X首 證Y條 方Z首」= 原书自报条数,**硬约束** |
| ③ | **影印原页目视核读** | 赵开美本影印原页逐篇核条界(取证,非推断) |

**算法只做高置信辅助**:不得用相似度阈值硬拍板条界。低置信条界必须人工核校。

### 「此版无」的细分原因(沿用既有六类,不得自创)
`选集未收` / `本版仅残卷` / `原书残损` / `体例不同` / `此版无此篇` / `暂未匹配`
—— 每条判「无」必须带**原文依据**,证据写进裁定文件。

## 五、编号空间与模块约定

```python
from . import skeleton as SK
SK.load_skeleton("shanghan")   # 伤寒 398 条
SK.load_skeleton("jingui")     # 金匮条级骨架
SK.n_items("jingui")           # 条数,取代硬编码 398
SK.skel_spec("jingui")         # 登记项(名称/编号空间/是否分层)
```

- 新增骨架 = 往 `骨架/骨架注册表.json` 加一项 + 一个骨架 json,**不改引擎代码**。
- 引擎任何模块**不得**出现字面量 `398`(《伤寒论》语境除外)。
- 骨架文件属**公共地基只读**,任何分包不得修改;发现错误 → 《争议与疑难清单》→ 总装裁决。

## 六、交付与回传口径

- 条级骨架回传后,**必须**给出:条数、每篇条数、每条的段数分布、每条的条界依据与置信。
