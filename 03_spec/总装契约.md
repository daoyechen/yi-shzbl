# 总装契约 · 公共地基

> 版本:1.0 ｜ 适用:《伤寒论》多版本对照体系
> 契约方:总装 ｜ 适用方:各版本包承接人

---

## 一、三层结构

```
00_公共地基/          ← 只读。总装独占修改权。任何包不得修改。
   骨架/宋本398条.json
   引擎/shjkit/
   规范/ 模板/

版本包_<版本名>/       ← 承接人独占。一人一包,零共享写。
   spec.json
   版本正文/*.md
   交付/  _工作/

总装产出/              ← 总装生成。承接人不得自行生成或修改。
   01_条文总表.json ... 对照浏览器.html
```

---

## 二、公共地基:三条硬约束

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | **骨架只读** —— 不得修改 `骨架/宋本398条.json` | 条号漂移 → 已交付各包主表全部作废 |
| 2 | **编号与字段不得自创** —— 沿用宋本 398 条条号、六类原因枚举、统一字段名 | 总装需做字段翻译 → 合并出错 |
| 3 | **不静默丢信息** —— 判不了就标 `[归属不确定]`,不许含糊带过 | 无法追溯,总装无法裁决 |

**发现公共地基的问题怎么办?**
写进本包 `交付/争议与疑难清单.md` 第五节「对公共地基的更正建议」,由总装裁决后统一改版重发。
**不许就地修改。**

## 三、版本包:交付标准

### 3.1 目录

```
版本包_<版本名>/
  spec.json
  版本正文/<NN>_<版本名>.md
  交付/
    版本对照.md  本版独有.md  锚点表.md  待复核.md
    体例说明.md  方剂表.md    版本包.json
    清单.md      原始资料索引.md  争议与疑难清单.md  SKILL.md
  _工作/
    单元.json  篇目.json
```

- 版本包目录名:`版本包_<版本名>/`
- 转录件编号:沿用已用号段,**接续不重排**(已用 01–08,新包从 09 起)
- 中间产物一律 `_` 前缀
- **包内不出现总装级文件**(主表、对照浏览器)

### 3.2 spec.json 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `版本名` | ✅ | 显示名,一经登记不改 |
| `文件` | ✅ | 转录件相对路径(相对包根) |
| `正文起点` | | 该版正文起始标志行**原文**;`null` = 选集起始即正文 |
| `篇目标记` | | 篇标题识别正则列表(行首匹配);`[]` = 无篇级层 |
| `收录范围.kind` | ✅ | 六类枚举之一,不得自创 |
| `收录范围.evid` | ✅ | **该版原文**依据,不是转述 |
| `收录范围.start` | | 仅 `选集未收` 用:条号小于此值者不在选集内 |
| `校记锚点` | | 该版校记是否含「同《宋本伤寒论》第X条」 |
| `编号形式` | | `无` / `逐位汉字` / `阿拉伯` |
| `切条策略` | | `auto` / `行段` / `逐行` |

### 3.3 交付前自检

```bash
python3 -m shjkit.verify <版本包目录>
```

必须全 ✅。`verify.py` 检查 8 项:
1. spec.json 存在且合法
2. 转录件存在且含页锚
3. 交付件 7 件齐全
4. 条号 1..398 无缺
5. 「此版无」原因合法
6. 「此版无」均有证据
7. 独有序 ID 合规无重复
8. 低置信已列入待复核

### 3.4 四件套(必填)

| 件 | 必含 |
|---|---|
| `清单.md` | DoD 逐项自检表(T1–T4 × 要求/实测/结论)+ 关键统计 + 双属性 + 「本组未做」表 + 一句话结论 |
| `原始资料索引.md` | 输入文件清单与使用情况 / 篇目命中索引 / 条级覆盖索引 / 新产出定位 / 对地基的更正建议 |
| `争议与疑难清单.md` | 冲突 / 需人工裁决 / 方法疑难 / 未决汇总(A·B·C 三档) / 本组未做 |
| `SKILL.md` | 该版专属判读经验(frontmatter + 什么时候用它 / 入口判定 / 核心判断 / 步骤 / 判断标准 / 不适用) |

## 四、总装:合并规则

### 4.1 合并

```bash
python3 -m shjkit.assemble <包1> <包2> ... --out <输出目录>
```

| 规则 | 说明 |
|---|---|
| 骨架唯一 | 以宋本 398 条为行,各版为列 |
| 字段直传 | 各包 `版本包.json` 用同一套字段名,总装**不做字段翻译** |
| 原因与证据原样带出 | 不改写、不合并、不"优化"措辞 |
| 独有不入主表 | 各版独有序单独成篇(`05_版本独有内容.md`) |
| 缺包即报错 | 一个包缺失 → 总装报错,**不静默跳过** |
| 版本名唯一 | 重复即报错 |

### 4.2 总装产出

| 文件 | 内容 |
|---|---|
| `01_条文总表.json` | 398 条 × N 版机器可读主数据 |
| `02_条文对照本.md` | 人读主文件 |
| `03_锚点表.md` | 校记硬锚点(主锚/副锚/附条分列) |
| `04_差异索引.md` | 有文字差异的条目 |
| `05_版本独有内容.md` | 各版独有序 |
| `06_方剂对照表.md` | 按方名聚合 |
| `07_各版条文清单.md` | 各版条次 + 对应宋本条号 |
| `08_待复核清单.md` | 低置信 + 暂未匹配 |
| `10_各版体例说明.md` | 体例与「此版无」依据 |
| `00_README.md` | 总览 + 统计 |
| `viewer_data.json` | HTML 浏览器数据源 |
| `对照浏览器.html` | 自包含单文件(离线可用) |

### 4.3 出浏览器

```bash
python3 -m shjkit.htmlbuild <输出目录>/viewer_data.json <输出目录>/对照浏览器.html
```

## 五、争议裁决

### 5.1 三档分类

| 档 | 含义 | 裁决人 | 例 |
|---|---|---|---|
| A | 可自动定性 | 承接人自行 | 全文检索确证无对应 → 改判「此版无此篇」 |
| B | 需人工裁决 | 承接人 + 总装 | 锚点圈码错位;两处读法谁正 |
| C | 方法论疑难 | 总装(必要时外部专家) | 「此版无」某原因是否应改判;繁简是否计入异文 |

### 5.2 标记体系(五类,不得自创)

`[归属不确定]` `[需原图核校]` `[体例存疑]` `[转录存疑]` `[已本组裁决,此处备案]`

**禁止**用 `TODO` / `[?]` / `待定` 等含糊标记。

## 六、版本包之间的冲突处理

多人并行时,**唯一可能的冲突是公共地基**。各包目录互不相干,不存在文件冲突。

| 情况 | 处理 |
|---|---|
| A 包发现引擎 bug | 写进 A 包争议清单,总装修复后**重跑全部包**并重发地基 |
| A 包发现骨架错误 | 写进 A 包争议清单,总装裁决后统一改版,**重发骨架**,各包重跑 |
| A、B 包对同一宋本条给出不同对应 | 各自是各自版本的独立判断,不冲突;若 A 用了 B 版的结论,须在 A 包索引中声明 |

**关键:引擎或骨架一旦变更,必须全部重跑。** 版本包与引擎版本须配套记录(见 6.1)。

### 6.1 版本配套记录

各包 `交付/清单.md` 中记录:

| 项 | 值 |
|---|---|
| 骨架版本 | `宋本398条.json` 的 md5 |
| 引擎版本 | `shjkit` 的版本号 / 提交标识 |
| 规格版本 | `spec.json` 的规范版本 |

**换引擎或换骨架 → 全部重跑。** 不许混用不同版本产出的包。

## 七、验收(总装侧)

合并后自查:

- [ ] 398 条 × N 版,条号无缺
- [ ] 各版对上条数与各包自报一致
- [ ] 「此版无」原因分布已出表
- [ ] 待复核清单条数 = 各包之和
- [ ] 独有序 ID 无重复、无跨版冲突
- [ ] HTML 浏览器可打开、筛选可用、深链可用
- [ ] 各包 `verify.py` 均全 ✅
