## 二、退回的五个缺陷（全在 notes 层）

### 缺陷 1：25/25 条的 `text` 都缺开头的 `【`

**每一条**都是这个形状：

```
n=1  text = 補曰】太陽者，天之巨陽也：彌綸萬物…
n=35 text = 補曰】《淺注》言宜髮膚表之汗…
n=44 text = 次男元犀按】桂枝湯本爲解肌，誤下後…
```

左括号 `【` 被吃掉，右括号 `】` 留着。**25 条无一例外。**

交付格式写明「`text` 繁体照录，**保留 `【補曰】`/`【正曰】`/`【蔚按】` 原标记**」。现在每一条开头都是残标记，下游既认不出是哪个标记，也做不了 `attr` 校验。

**这是正则的锅，不是判断的锅。** 大概是切段时 `【` 当分隔符吃掉了、`】` 留在了正文里。改一行的事。

### 缺陷 2：55 段只入 25 段，丢了 30 段（含 9 个唐容川段）

转录全文里有 **55 个标记段**，`notes` 只有 **25 条**。

处理日志写明了原因：

> 按契约 n 唯一：同一条的多个注文段取最长段入 text，其余留在转录全文，不虚增条数。

**这条口径是错的，契约不是这么写的。** `交付格式` 里 `seg` 字段就是为这个存在的：「`seg`：一条下多段时从 1 连续递增；不拆不写」。他没用 `seg`（字段集只有 `attr/n/pg/text/versions`）。

**后果不是「少几条」，是把不同注家的话删掉了。** 实证：

| 条 | 保留了 | 丢掉了 |
|---:|---|---|
| n=29 | `正歸`（唐容川）307 字 | `蔚按`（陈修园）293 字 |
| n=30 | `正曰`（唐容川）805 字 | `張令韶云`（引文）345 字 |
| n=35 | `補曰`（唐容川）503 字 | `蔚按`×2（陈修园 218+242）＋`張令韶云` 24 ＋ `柯韻伯` 133 = **617 字** |

n=35 一条就丢了 617 字的陈修园与引文。

全批统计：转录全文 **唐容川段 22 个**（補曰 13 ＋ 正曰 8 ＋ 正歸 1），`notes` 里 `attr=唐容川` 只有 **13 条**。**至少 9 个唐容川本人的段没进去。**

本包的立项目标就是取唐容川的话。这个口径直接打掉了它。

### 缺陷 3：`正歸` 判成 `引文`，应为 `唐容川`

n=29 的 `attr=引文`，但那段是 `正歸`（＝`正曰` 的 OCR 变体，歸/曰 形近）。

`attr` 判据的白名单里只有 `補曰`/`正曰`，没兜住 `正歸`。同一条属于「唐容川本人语」，被标成引文后下游筛不出来。

### 缺陷 4：`n=31` 段内混入 `{蔚按】`

该条正文里有一个多余的花括号：`{蔚按】`。同类问题在批次1 成无己那份出现过（`（注N·…）` 标记泄漏进 text），入库前必须洗掉。

### 缺陷 5：15 条既不在 `notes` 也不在未覆盖清单 —— 静默丢失

`未覆盖条清单_批1.md` 全文只有一行：

```
| 1-5 | 辨太阳病脉证并治上 | 本包范围外/节下合并 | … |
```

实际核对：

- 本批应覆盖 **条 1–44**
- `notes` 有 25 条
- 清单交代 5 条（1–5）
- **剩下 15 条（7、8、9、10、11、16、17、18、19、21、25、33、36、40、42）既无 notes、也不在清单里**

这违反任务书 §六 边界第 9 条「本包每一条都要有归处」和硬规矩「不静默丢信息」。

**另外清单自身有冲突**：条 1 既在 `notes` 里（有注文），又被列进未覆盖清单。郝万山那次条 104 是同样的错法。

## 四、修法（明确到可执行）

1. **`text` 保留完整 `【標記】`** —— 切段时用 `【([^】]+)】` 整段匹配，别把 `【` 当分隔符吃掉
2. **一条多段用 `seg`** —— 同一条下 N 段就出 N 条记录，`seg` 从 1 递增；`attr` 逐段各自判。**不许「取最长段」**
3. **`attr` 白名单加 `正歸`**（及其他 OCR 变体：`正白`/`正臼`/`正晶`/`正插` 等已知形）
4. **洗掉 `{`/`}` 等非标记括号**
5. **未覆盖清单补全**：本批 19 条未出注的，逐条写明原因（`原书未注（仅原文与浅注，无标记段）` / `本包范围外`）；**条 1 从清单删掉**
6. **修正表补 `餘`/`幹` 判定 + 方剂专名表**，重出 `修正规则命中表_批2.md` 时一并报
