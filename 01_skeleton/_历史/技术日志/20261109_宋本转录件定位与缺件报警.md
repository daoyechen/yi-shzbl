## 一、背景：一个静默故障

`assemble.py` 第 136 行原为：

```python
SONGBEN_FILE = "/workspace/output/伤寒论版本大全/版本正文/07_宋本伤寒论.md"
```

第 145 行：

```python
if not os.path.exists(songben_file):
    return []          # ← 静默返回空
```

**两个问题叠在一起**：

1. 绝对路径硬编码，换环境即失效
2. 缺件时不报警、不报错，产物看起来完全正常

### 后果链

```
宋本转录件缺失
  → song_pians() 返回 []
    → spian 空列表（应为 12 篇）
      → spianMap 全 null
        → pian 的 sp 字段 null、own 误判为 1（5 个版本受影响）
          → 09_篇级对照.md 缺"宋本无条号篇"整节
            → viewer_data.json 少 3,072 B
```

**用户可见的后果**：HTML 里「宋本无条号篇」区块是空的，篇级对照表缺一节。

**发现难度**：极高。如果不做逐文件字节比对，永远不会发现——总装会打印「总装完成:398 条 × 9 版」，一切正常。

### 目录层级（踩过的坑）

```python
# 第一次写错：只上溯 2 层，落到 引擎/
_FOUND_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))

# 正确：上溯 3 层，落到 00_公共地基/
_HERE       = os.path.dirname(os.path.abspath(__file__))   # 引擎/shjkit/
_ENGINE     = os.path.dirname(_HERE)                       # 引擎/
_FOUND_DIR  = os.path.dirname(_ENGINE)                     # 00_公共地基/
```

> 这个 bug 是被刚加的「缺件报警」当场抓到的。上一版会静默失败，谁也不会知道。

### 兼容性

保留绝对路径作为查找链最后一环。理由（原方建议）：
- 可配置链保可移植
- 绝对路径保兼容

## 六、教训

**静默失败比报错危险得多。**

这个缺陷存活了很久，因为：
- 程序不报错
- 产物文件都生成了
- 大小看起来也正常（只差 3 KB / 3 MB 的 0.1%）

唯一能发现它的方法是**逐文件字节比对**。

建议把「产出必须与基线逐字节一致」写进总装验收标准，而不是只看「有没有生成」「数字对不对」。
