# 变更记录 · 引擎加骨架参数（v1.1-local）

> 日期：2026-11-09　对象：`00_公共地基/引擎/shjkit/assemble.py`、`htmlbuild.py`
> 目的：让总装支持 `--骨架 <id>`，为双区（SH + JG）做准备

---

## 一、为什么改

交接答复 §3.2 指出：`skeleton.py` 已多骨架化（`skel_spec(id)` / `load_skeleton(id)` / `n_items(id)` 均支持传 id），但上层没透传：

| 位置 | 原文 | 问题 |
|---|---|---|
| `assemble.py:31` | `SKEL_NAME = SK.skel_spec()` | 模块级常量，恒取 SH |
| `assemble.py:265` | `items = SK.load_skeleton()` | 不传 id |
| `assemble.py:349/441/572/573/578/591` | `SK.n_items()` / `SK.skel_spec()` | 不传 id |
| `htmlbuild.py:13` | `_sk = SK.skel_spec()` | 不传 id |

**所以底层就绪、上层卡住——改造量比原答复估计的小。**

---

## 二、改了什么

### assemble.py（4 处调用 + 2 处 argparse）

| # | 变更 |
|---|---|
| 1 | 删除模块级 `SKEL_NAME` 常量 |
| 2 | `def assemble(pkg_dirs, out_dir)` → `def assemble(pkg_dirs, out_dir, skel_id=None)` |
| 3 | 函数内新增 `SKEL_NAME = SK.skel_spec(skel_id).get(...)` |
| 4 | `SK.load_skeleton()` → `SK.load_skeleton(skel_id)` |
| 5 | 全部 `SK.n_items()` → `SK.n_items(skel_id)`（6 处） |
| 6 | `_spec = SK.skel_spec()` → `SK.skel_spec(skel_id)` |
| 7 | `main()` 加 `--骨架` / `--skel` 参数解析，透传到 `assemble()` |
| 8 | 用法提示更新 |

### htmlbuild.py（4 处 + 修 1 个 bug）

| # | 变更 |
|---|---|
| 1 | argv 解析提到 `_sk` 计算之前 |
| 2 | 加 `--骨架` / `--skel` 解析，`SKEL_ID` 传入 `SK.skel_spec()` |
| 3 | **修 bug**：`DST = sys.argv[2]` → `argv[1]`。原写法在带 `--split` 时取错位 |
| 4 | 骨架名、骨架类型（分层/子层）随 `--骨架` 切换 |

**兼容性**：不传 `--骨架` 时行为与改造前完全一致（`skel_id=None` → 默认取注册表第一个，即 `shanghan`）。

## 三、回归测试

### 测试 1：SH 版重建（不传 `--骨架`）

```
python3 -m shjkit.htmlbuild /tmp/viewer_data_sh.json /tmp/rebuild_sh.html
```

| 验证项 | 结果 |
|---|---|
| 生成成功 | ✅ 1,317,980 B |
| DATA 对象 vs 源 viewer_data.json | **完全相等** |
| items 条数 | 398 = 398 ✅ |
| 16 个键 | 全部一致 ✅ |

**结论：引擎没破坏数据。**

### 测试 2：`--骨架 jingui` 参数生效

```
python3 -m shjkit.htmlbuild ... --骨架 jingui
```

骨架名由「宋本《伤寒论》398 条」切换为「赵开美本《金匮要略方论》条级骨架」。✅

### 测试 3：与现有 index.html 比对

| 键 | 结果 |
|---|---|
| items（398 条） | **逐条完全一致** |
| fang / fangStat / indep / pian / spian / spianMap / stats / notes / cover / reason | 一致 |
| **vers** | 集合相同、**顺序不同** |
| **review** | 97 条内容相同、**排序后完全一致** |
| expect / numberedPian / skel | viewer_data 有、index.html 无（旧版产物缺 3 键） |

**vers 两种顺序**：

```
viewer_data : 唐本、康平本、康治本、敦煌本、桂林古本、注解伤寒论、脉经本、金匮玉函经、高继冲本
index.html  : 唐本、康平本、金匮玉函经、高继冲本、注解伤寒论、脉经本、桂林古本、康治本、敦煌本
```

**判断：这是排序规则变更，不是数据错误。** 重建后界面版本 tab 会按 viewer_data 顺序走。已在 `追问_r2.md` 第 4 条要求原方确认。
