# C6a 版本判同 · 派发包（宋元明刊本组）

> 发给承接人只需 **`47_派发包_C_版本判同_C6a_人工.zip`**（约 15 MB），解压即用。
> 承接人从 `任务书.md` 开始读。

## 这包要解决什么

`_待验/` 里一批自称「宋刊」「元刊」的旧本，共 6 件。
要判清每件**到底是什么形态、什么版本**——是真旧刊、是影印、是排印，还是书商加的头衔。

判对了，宋元刊本是 L1 最上层的一级证据；判错了，等于给骨架塞假件。

## 为什么这批最要紧

`_待验/` 现有 207 件，按价值分七区。这一区（`02_宋元明刊本`）是**唯一可能改写版本谱系的一组**：
其余各区多是注本、电子本、同名异刻，只影响台账；只有这组能补上「伤寒侧没有宋元旧刊影像」这个空缺。

## 为什么要盲判

原文件名里直接写着「宋版」「元版」「南宋刊」「元刊」——那是藏书目录或图录的标注，
**标错版本是常态**，且错得最有规律：明翻宋标成宋、日本影印标成原刻、清抄标成宋抄。

所以：
- 判读页目录改成纯编号 `C6a-001` … `C6a-006`
- `清单.csv` 只给编号与页数，**不给文件名**
- 编号对应表 + 页序映射留在项目内 `_盲码对应表_不发包.md`，**不进 zip**
- 自检脚本会拒绝「依据里出现文件名」的交付

## 自检覆盖

条数 / 编号 / 必填字段 / 判定取值 / 载体取值 / 依据≥2项 / 页号真实存在 / 无文件名引用。

实测：一份故意写错的交付被拦下 7 处（「疑似同版」这种自创判定、载体写「刻本」、p999 不存在页、条数少一条…）。

## 打包注意（给发包方）

- 用 Python `zipfile`（`00_公共地基/引擎/mkzip.py`），**不要用 `zip` 命令**——中文名会乱码。
- 目录项须设 `external_attr = (0o40755 << 16) | 0x10`，否则解压后只读。
- **`_盲码对应表_不发包.md` 不进 zip**（打包时用 `--skip`）。
- 打完用全新目录解压一次，独立跑 `工具/自检.py`，确认自足。
