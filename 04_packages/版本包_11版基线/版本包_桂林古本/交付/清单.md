## 七之二、复跑顺序（**顺序错了会前功尽弃**）

`pkgbuild` 每次都会重写 `交付/体例说明.md`、`交付/方剂表.md`、`交付/锚点表.md`、`交付/待复核.md`、`交付/本版独有.md`、`交付/版本对照.md` 六个文件。**人工版的内容必须在 `pkgbuild` 之后才生成**，否则会被引擎版覆盖。

本轮实际踩过这个坑：最后一次 `pkgbuild` 把已写好的 65 KB 人工方剂表和锚点表、体例说明订正节一起冲回引擎版（方剂表 65,502 → 35,551 字节、锚点表 17,930 → 508 字节）。已重跑生成器恢复并复验。**正确顺序如下，不可调换：**

```bash
# 0. 正文修订只做一次（幂等，从 _工作/正文_修订前.md 重新生成）
python3 工具/e1_fix.py

# 1. 引擎建包 —— 会清掉旧的《最终版本包.json》与上述六个交付 md
python3 -m shjkit.pkgbuild ../../版本包_桂林古本二轮

# 2. 叠加人工裁定 —— 只写《最终版本包.json》，不动交付 md
python3 -m shjkit.overlay  ../../版本包_桂林古本二轮

# 3. 生成人工版交付 md（全在 pkgbuild 之后！）
python3 工具/c1_fang.py     # 抽方（方名→药味→右×味），出 _工作/方剂_V.json
python3 工具/c3_guishu.py   # 四类归属，出 方剂归属表.md + _工作/方剂归属.json
python3 工具/g1_fang.py     # 方剂表.md + 人工裁定.json 方剂层（依赖上面两个 json）
python3 工具/i1_anchor.py   # 锚点表.md
python3 工具/h1_diben.py    # 底本差异清单.md
python3 工具/h2_pianmu.py   # 篇目勘误表.md
python3 工具/h3_index.py    # 原始资料索引.md

# 4. 体例说明的「订正节」是手写在 pkgbuild 之后的，重跑 pkgbuild 后须补回（本文件 §「A2 第二轮订正」）
# 5. 校验
python3 -m shjkit.verify   ../../版本包_桂林古本二轮
```

> 另：`g1_fang.py` 会读 `交付/版本包.json`（引擎版）来取 26 条伪目、再以「伪目(已删)」写回人工裁定，所以它也必须在 `pkgbuild` 之后跑。`f1_decide.py`（T4 条目层）会整份重写 `人工裁定.json`，若重跑它，**必须再跑一次 `g1_fang.py` 把方剂层补回**。
