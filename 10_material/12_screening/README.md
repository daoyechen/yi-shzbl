# 12_screening · 待验区筛选记录

对 `_待验/`（NAS 那 220 件）做过一次全量筛选：**哪些相关且尚未收录（留）、哪些重复或不相关（删）**。

它不是物料，是**关于物料的判断**——所以跟 `15_catalog/` 同族，都留在物料层。

## 跟 15_catalog 的区别

| | 记什么 |
|---|---|
| `15_catalog/` | 每件**是什么**：题名、版本、藏馆、能否当底本 |
| `12_screening/` | 每件**该不该留**：留下、删除、高价值待深挖 |

两份合起来才能回答"这批藏品里，哪些能用、哪些可以清掉"。

## 内容

| 文件 | 是什么 |
|---|---|
| `32_待验区筛选报告.md` | 筛选方法、依据（`书单_四象限.md`＋`11_缺书清单_总书谱系.md`＋`index.html`）、结论 |
| `30_待验区逐件台账.csv` | 逐件判定 |
| `33_高价值保留件清单.csv` | 值得深挖的件 |
| `34_删除清单_可复原.csv` | 判定可删的，附复原路径 |
| `31_书名索引_可扩展医籍.csv` | 书名索引 |
| `classify.py`／`reorg.py`／`probe_text.py` | 本次筛选用的脚本。**一次性判定脚本，不是通用引擎**——所以跟着记录走，不进 `08_tools/` |

## 为什么入库

`34_删除清单_可复原.csv` 是不可再生的：删了哪些件、为什么删、从哪能复原，只有这一份。丢了就不知道 `_待验/` 少过什么。

物料本身不入库（在 NAS 有实体），但**判断要留**——跟 `15_catalog/` 同一个理由。
